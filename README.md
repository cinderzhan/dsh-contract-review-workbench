# 合同审核工作台

DSH Desktop 合同审核工作台。源码和预构建客户端可从本仓库安装。

## 使用流程

1. 上传 TXT、Markdown、DOCX 或含文本的 PDF，也可粘贴合同。文件上限 15 MB，PDF 上限 150 页，提取文本上限 60,000 字符。不支持扫描件 OCR。
2. 选择通用、采购、服务或租赁模板，修改规则、审核立场及补充要求；从 DSH 已配置模型中选择审核模型，也可跟随 DSH 默认模型。
3. 首次点击 AI 审核时，在系统目录选择器中指定该合同 AI 会话的资料文件夹。取消选择不会启动审核；后续审核可沿用当前合同的会话。旧版本建立的会话会在下一次审核前要求重新选位置，原有会话和合同记录保留；规则页可手动更换位置。查看问题及原文引用。未审核、失败与零问题分别显示。基础关键词检查作为独立辅助功能。
4. 修改稿默认沿用本次审核模型，也可单独选择。生成 AI 修改建议，左右比较原文与建议稿，逐条接受或拒绝。导出 DOCX 只包含已接受修改，原文保留。

上传合同后，为当前合同选择一次项目文件夹。原文、审核记录、已接受的修订稿和项目状态将自动保存到该文件夹下的 `合同审核工作台/<项目 ID>/`；不会自动触发浏览器下载，最后一步可手动下载。Desktop 的 IndexedDB `dsh-contract-review-workbench-v1` 仍保留历史记录。旧项目需在上传页明确选择文件夹后才会写入该位置。文档导入和导出保留文本内容，不承诺保留原始排版。AI 功能使用所选的 Desktop 模型，会将合同及审核要求发送给该模型服务；本地存储不代表模型推理离线。

原生对话默认收起，通过“审核助手”打开。带入上下文仅插入草稿、不自动发送，不清空已有文字或引用。每份合同关联独立工作台会话。AI 失败会显示错误，不冒充零风险结果。修改建议中的待确认事实需要人工补充。

## 构建与验证

```sh
npm run check
node scripts/check-workbench-package.mjs
pnpm pack
```

服务端需要宿主 `@deepseek-ai/dsh-llm >=0.1.7-rc.2`。使用当前 Desktop 的本地 tarball 安装能力安装生成包并重启 Harness。工作台身份沿用旧版，用户不需重新填写项目资料。

源码仓库：https://github.com/cinderzhan/dsh-contract-review-workbench 。示例合同均为虚构内容。

## 使用范围与数据

已在 DSH Desktop 0.10.0-test.20260927 / Harness 0.1.7-rc.2、macOS Darwin 24.3 arm64 安装并打开；其他平台未验证。合同、规则、审核结果和修改决策保存在所选项目文件夹与本机 Desktop IndexedDB。AI 审核会将合同、规则与审核要求发送到用户在 DSH 中选择的模型提供方，可能产生该提供方的费用；请先确认模型服务的条款与隐私要求。扫描 PDF 不支持 OCR，DOCX 导出不保留原始排版。审核结果需人工复核。卸载工作台不会主动删除本机业务记录或宿主会话。
